6.2 如何选择迭代求解器？

求解器不是按名字挑选的。先判断矩阵是否对称、正定、稀疏或只能矩阵自由访问，再把这些结构映射到算法的数学前提和软件 API。

  • 可视化推导
  • Python / MATLAB
  • 证据清单随页附带
先问矩阵是什么，再问软件有什么。同一个求解器在满足假设时是高效工具，在不满足假设时可能没有收敛保证。

五个结构问题决定算法候选集

  1. 是方阵系统，还是矩形最小二乘问题？
  2. 矩阵是否对称（复数情形为 Hermitian）？
  3. 是否正定，还是可能不定或奇异？
  4. 矩阵是否稀疏？是否只能提供矩阵向量乘法？
  5. 精度目标是什么，能否构造有效预条件器？

这些不是软件选项，而是算法的数学前提。把一般矩阵交给 CG，不是简单地“收敛慢一点”，而是违反了 CG 的适用条件。

从 NETLIB/templates 到现代 API

Demmel 原书在 1997 年的语境下指向 NETLIB/templates，帮助用户比较迭代算法和软件。今天可从 SciPy 的 scipy.sparse.linalg、PETSc 等官方文档开始。关键不是记住一个函数名，而是核对矩阵前提、停止条件、预条件器约定和返回状态。

读 API 时的四项检查

  • 适用矩阵：CG 要求对称/Hermitian 正定；GMRES 可用于一般方阵系统。
  • 停止准则：看清使用的是相对残差、绝对残差还是预条件残差。
  • 预条件器：CG 的预条件器也必须满足相应的对称正定条件；通常传入近似逆的作用，而不是显式求逆矩阵。
  • 返回状态：达到迭代上限不等于收敛；检查 info 并独立计算真实残差。
from scipy.sparse.linalg import cg

x, info = cg(A, b, rtol=1e-8, atol=1e-12, maxiter=500, M=M)
true_residual = norm(b - A @ x)
if info != 0:
    raise RuntimeError(f"CG did not converge: info={info}")

示例展示 API 的使用结构；运行前必须确认 A 与 M 满足所安装 SciPy 版本文档中的约束。
